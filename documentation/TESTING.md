# Testing

All results below were produced on 2026-11-06 on Windows 11 Pro (26200), Node 24.22, .NET SDK 10.0.403, against the local dev server and embedded PostgreSQL 18.

## Scanner — 57/57 (`apps/desktop/tests/Screensharing.Scanner.Tests`)
Synthetic fixtures are real files built on disk: a Prism-style selected instance, a **second instance containing Meteor Client**, and an **"Unrelated" folder** (documents, downloads) containing Wurst, a native injector and text naming cheat clients. Jars contain structurally valid class files with real constant pools; executables are fake PE images (never run). No real cheat binaries are used.

* **Scope (ScopeTests):** only the selected instance is inspected — every path that passed the scope guard lies in the instance or is an attested class-path file; other instance and unrelated folders never appear in the access list, custody log, inventory or findings; the scope refuses outside paths, `..` traversal and prefix tricks; a junction from `config/` to Documents is **not followed** (reported as not inspected); a redirected `mods/` junction **is** followed and reported; an unresolved instance is refused (`InstanceNotResolvedException`) instead of falling back.
* **Instance identification:** Modrinth App (from a command line recorded on this machine), Prism (working directory + `instance.cfg`), official launcher, CurseForge; missing `--gameDir` with unreadable working directory, non-existent directory, non-game directory and unreadable command line produce explicit reasons; IDE/Gradle Java processes are ignored; working directory and `JAVA_TOOL_OPTIONS` are read from a **live process** while an unrelated variable is not; account tokens are redacted.
* **Negative cases:** clean Fabric instance with configs, an opaque resource pack and a log whose **chat** line names cheat clients → **0 findings**; a mod with ambiguous names (Reach, Speed, Velocity, Timer) → nothing; a single generic indicator (`java/awt/Robot`) → not reported; an unrecognised mod → informational only.
* **Known clients:** Meteor confirmed with corroborating mod id + package + mixin config + constant-pool strings; Wurst renamed as `sodium-…jar` → confirmed + disguised; LiquidBounce with **stripped metadata and obfuscated class names** identified by its mixin configuration (high confidence); LiquidBounce inside a Jar-in-Jar; unknown client with module layout (high confidence).
* **Evasion:** impersonation of Sodium's id without Sodium's packages; 8 encrypted class entries; a PE disguised as `icon.png` inside a mod with injection-API strings (scored, capped below confirmed); a PE named `.jar`; a PE with an appended jar (polyglot); a native injector disguised as `config/cache/textures.dat`; a jar with an "anti-unzip" end record still identified as Wurst; inconsistent fabric metadata; jar with `.txt` extension; Java agent manifest; obfuscated archive; community injection-client string (low confidence only).
* **Instance artifacts, logs, packs:** `meteor-client/` and `wurst/enabled-hacks.json`; cheat in a session mod list, removed mod, Wurst stack trace in a log, **the same text in a chat line ignored**; Meteor in a crash report; X-ray pack detected **by content** in a renamed zip (transparent textures, enabled in options.txt) and a folder pack (empty block models); X-ray pack and shader names; Freecam with policy severity; modified client jar on the class path; mod changed after last session; duplicate ids.
* **Honesty:** a corrupt jar and a password-protected jar are reported as *Unable to inspect* and counted; disabled rules never report; every finding carries location and signature.
* **Engine:** monotonic progress and file counters, excluded folders never read, stages without a process skipped with reasons, **cancellation** mid-scan leaves every file byte-identical and releases the scope, statistics equal the inspection records, chain of custody, deterministic ids, manifest identical to the TypeScript implementation, embedded ruleset valid.
* **Parsers:** Aho–Corasick, class-file constant pool, signature scopes incl. UTF-16 in binaries, PNG alpha, archive probe, scoring rules, live `ReadProcessMemory`.

## Live instance (opt-in `SSME_LIVE_INSTANCE=1`)
Minecraft 1.21.11 (Fabric) running from the **Modrinth App** on this machine was identified from its process (`--gameDir …\ModrinthApp\profiles\sarni modpack`, 85 class-path entries) and scanned in **13 s**: 1,295 files examined, 455 analysed, 840 skipped (not code), 0 unable to inspect; 76 of 85 class-path jars hash-verified against the launcher's manifest; 144 native modules and 1 GiB of memory examined; **0 scope violations**. Findings: a real X-ray resource pack detected by content (17 see-through terrain blocks, high confidence) and by name (low), one mod removed since an earlier session, 11 unrecognised mods (informational). This run exposed and fixed three real problems: memory false positives from vanilla words, X-ray packs that use hollow models, and "anti-unzip" archives that .NET refused.

## Desktop — 4/4 (`apps/desktop/tests/Screensharing.Desktop.Tests`)
* `Pin_connect_scan_upload_and_report_roundtrip` — the desktop's own `ApiClient`/`InvestigationSession` against the local server: PIN claim, consent, live catalog, scan of the fixture instance, upload; the server shows the selected instance, inspection counts, and for Meteor the outcome `CONFIRMED`, location `mods/meteor-client-0.5.8.jar` and its signature; verified manifest; desktop staff view and PDF/JSON/CSV exports.
* `Upload_survives_a_network_interruption_mid_scan` — 6 injected transport failures; the client reconnects and the server receives every finding with a verified manifest.
* `Running_instance_scan_uploads_and_validates` (opt-in `SSME_E2E_FULL=1`) — the instance running on this machine scanned and uploaded; manifest verified; no scope violations.
* `Render_all_screens` — lays out all screens inside the real `MainWindow`; with `SSME_UI_SNAPSHOTS=1` writes `documentation/screenshots/desktop/*.png`.

## Website — unit 21/21, API end-to-end 18/18
Unit (vitest): PINs, semver, manifest vector, strict payload validation, rule validation, exports (CSV injection, PDF non-Latin text, new columns), verdicts never say "cheater" and an empty result is "No evidence detected … not proof", outcome mapping. API end-to-end (`tests/e2e/api-flow.test.mjs`) against the local server: accounts, CSRF, admin auth, PINs, authorization, single-use claim, consent, SSE, evidence validation and idempotency, completion and manifest, exports, PIN expiry, interruption recovery, blocked versions, brute-force limit.
